# R4 — เพิ่ม/ลบ/ซ่อน/เรียงสินค้าและบริการ, รายการในหน้า และอัปโหลดรูป

วันที่ 1–2 ตุลาคม 2026 · ส่วนที่สี่ของงานออกแบบใหม่ ตามทางเลือก A ใน [R4-M4-M5-PROPOSAL.md](R4-M4-M5-PROPOSAL.md): เก็บทุกอย่างเป็นเอกสาร JSON ต่อยอดจาก M3 การเปลี่ยนทุกอย่างเป็นร่าง เผยแพร่จึงมีผล (M4)

## สิ่งที่ได้

- **แพ็กเกจและสิทธิประโยชน์** (ปุ่ม "แพ็กเกจและสิทธิประโยชน์" บนแถบ editor, `src/components/editor/CatalogManager.tsx`)
  - แพ็กเกจเรียงตามหมวด › กลุ่ม (ชื่อกลุ่มตามหัวข้อในหน้า) พร้อมราคาและสถานะ
  - เลื่อนขึ้น/ลง ภายในกลุ่ม (เก็บเป็นเอกสาร `catalog` ลำดับแพ็กเกจ ไม่แก้ตัวแพ็กเกจ)
  - แสดง/ซ่อน (ซ่อน = `review.status: hidden`; แสดงกลับเป็น "ยังไม่ยืนยัน" จนกว่าจะเปลี่ยนเป็นยืนยันแล้ว)
  - ลบ: ลบไม่ได้ถ้าการ์ดโปรในหน้าแรกยังใช้ (บอกเหตุผล) ส่วนแพ็กเกจที่ลบในร่างแสดงในรายการ "ลบในร่าง" พร้อมปุ่มเอาคืน
  - เพิ่มแพ็กเกจในกลุ่ม: แพ็กเกจใหม่เริ่มแบบ **ซ่อนและราคา 0** ไม่คัดลอกราคา/เงื่อนไขจากแพ็กเกจอื่น Admin กรอกเองทั้งหมด แพ็กเกจที่แสดงบนเว็บ **ต้องมีราคามากกว่า 0** (ตรวจตอนบันทึกและตอน build)
  - สิทธิประโยชน์: เพิ่ม (เลือกไอคอนจากคลังสื่อ), แก้ชื่อ/ไอคอน, ลบได้เมื่อไม่มีแพ็กเกจใช้
- **รายการในหน้า** (`src/components/editor/list-edit.ts` + แผงแก้ไข): FAQ, เมนู, การ์ด, ขั้นตอน, ฉากหนัง 1–4, แท็บและการ์ดโปร, ลิงก์ footer ฯลฯ มีปุ่มเลื่อนขึ้น/ลง ลบ และ "+ เพิ่ม (คัดลอกจากรายการสุดท้าย)" ตามขอบเขตของ schema (เช่น ฉากหนัง 1–4, แท็บโปร 1–4, การ์ดในแท็บ 1–8); รายการที่จำนวนตายตัว (การ์ดบริการ 4 ใบ, คอลัมน์มือถือ 2) เรียงได้อย่างเดียว รายการที่เพิ่มได้ id ใหม่ทั้งตัวและภายใน (รวมรหัสติดตามปุ่ม) จึงไม่ซ้ำของเดิม
- **อัปโหลดรูป** (คลังสื่อ › "อัปโหลดรูปใหม่"): เลือกไฟล์ JPEG/PNG/WebP/AVIF ไม่เกิน 8 MB, ชนิดของรูป, คำอธิบายไทย/อังกฤษ (บังคับ) — server ตรวจสิทธิ์ Admin, อ่านไฟล์ด้วย sharp (ไม่รับภาพเคลื่อนไหว/SVG), หมุนให้ตั้งตรง, ย่อกว้างไม่เกิน 2400 px, แปลงเป็น WebP แล้วเก็บใน Supabase Storage bucket `media` ด้วย session ของ Admin (ชื่อไฟล์สุ่ม ไม่ทับไฟล์เดิม) รูปเข้าคลังสื่อเป็นร่าง `media:upload-…` และถูกเลือกทันที

## ข้อมูลและฐานข้อมูล

- เอกสารใหม่ `catalog` (`{ order: [รหัสแพ็กเกจ…] }`) และการเพิ่ม/ลบเอกสาร `package:` `media:` `benefit:` — ร่างของเอกสารที่ยังไม่มีคือการเพิ่ม ร่าง `{"$deleted": true}` คือการลบ (tombstone) ทั้งสองผ่านการตรวจ schema และการอ้างอิงข้ามเอกสารเหมือนการแก้ปกติ ร่างลำดับใช้หลังสุด เพื่อให้เรียงแพ็กเกจใหม่ได้
- รูปแบบเนื้อหายังเป็นรุ่น 3 (ไม่มีเอกสารไหนเปลี่ยนรูป)
- migration `supabase/migrations/20261001160000_catalog_and_media.sql`: ให้ `content_drafts` รับเอกสาร `catalog`, สร้าง bucket `media` (อ่านสาธารณะผ่าน URL, รับเฉพาะ WebP ไม่เกิน 8 MB) และ policy ให้เฉพาะ active Admin อัปโหลด/แทนที่/ดูรายการ/ลบ — pgTAP `supabase/tests/database/catalog_and_media.test.sql` (13 ข้อ)
- `npm run db:start` เปิด storage-api แล้ว (เดิมปิด) เพราะต้องใช้กับการอัปโหลด
- `src` ของรูปรับไฟล์ของเว็บ (`/…`) หรือ URL ของ bucket `media` (https; http เฉพาะ 127.0.0.1/localhost ของ local stack) และ `next.config.ts` อนุญาต host ของ Supabase ที่ตั้งไว้ให้ `next/image`
- **เจ้าของต้อง apply migration นี้ที่ dev project** (`npm run db:push:dev` แล้ว `npm run db:push:dev:apply`) ก่อนใช้การอัปโหลดและลำดับแพ็กเกจที่นั่น

## รูปจาก Google Flow (S1–S8)

เจ้าของส่ง S1–S8 และรูปแนวตั้ง 8 ไฟล์ในโฟลเดอร์ Drive "ส่งไฟล์ที่นี่" เมื่อ 2 ต.ค. ตรวจแล้ว S1–S8 ไม่มีตัวอักษร โลโก้ หรือจุดเพี้ยน แปลงเป็น WebP กว้างไม่เกิน 1920 px ใน `public/media/flow/` (รวม ~0.9 MB) เข้าคลังสื่อเป็น `flow-s1-…` ถึง `flow-s8-…` (ชนิด `generated`) แล้วใช้กับการ์ดโปรทุกแท็บ (ยกเว้นโซลาร์ที่ใช้ภาพถ่ายจริง) และการ์ดบริการ 3 ใบ รูปชั่วคราวเดิมจากเว็บเก่ายังอยู่ในคลังสื่อให้เลือกได้

รูปแนวตั้งยังไม่ได้ใช้ (การ์ดและการ์ดบริการครอปแนวนอน) และพบปัญหา: `Friends_sharing_video…-mobile` ภาพซ้อนสองชั้นมีรอยต่อกลางภาพและไม่มีคน, `Woman_working…-mobile` ด้านบนเป็นแถบสีม่วงเรียบ (รอยขยายภาพ), รูปแนวตั้งหลายรูปเป็นห้องว่างไม่มีคนต่างจากแนวนอน

วิดีโอ `true_fiber_simplified_15s.mp4` (29 MB) ดาวน์โหลดผ่านเครื่องมือ Drive ไม่ได้ (จำกัด 10 MB) — ต้องวางไฟล์ไว้ในเครื่องจึงจะแปลงเป็นหนังหน้าแรกได้ (prompt 5)

## ทดสอบ

- Unit: เพิ่ม/ลบ/เรียงเอกสาร, tombstone, ลำดับใช้หลังสุด, ลบสิ่งที่ยังถูกใช้ไม่ได้, ขอบเขตรายการจาก schema, การคัดลอกรายการพร้อม id ใหม่, autosave ของแพ็กเกจใหม่/ลำดับ/การลบบันทึกครั้งเดียว (พบและแก้ bug ที่เอกสาร `catalog` ถูกสร้าง object ใหม่ทุกครั้งทำให้บันทึกวนไม่จบ)
- E2E (`admin-editor.spec.ts`): รายการ FAQ เพิ่ม/เลื่อน/ลบได้ และการ์ดบริการ 4 ใบเพิ่ม/ลบไม่ได้, เพิ่มแพ็กเกจแล้วแสดงไม่ได้จนกว่าจะใส่ราคา แล้วเห็นในตัวอย่างหน้า /broadband และลบได้ ส่วนแพ็กเกจที่การ์ดหน้าแรกใช้ลบไม่ได้, อัปโหลดรูปแล้วรูปเข้าคลังสื่อและขึ้นบนการ์ดในตัวอย่าง
- pgTAP: 97 ข้อผ่าน (รวมของ R4 13 ข้อ)

## ข้อจำกัดและงานต่อ

- แพ็กเกจที่สร้างใหม่ยังไม่มีหน้ารายละเอียด `/packages/<รหัส>` จนกว่า M4 จะให้หน้าเว็บอ่านฉบับเผยแพร่ (หน้ารายละเอียดตอนนี้สร้างตอน build)
- การลบรูปที่อัปโหลดออกจาก Storage ยังไม่ทำ (ไฟล์ที่ release เก่าอ้างถึงต้องคงอยู่เพื่อย้อนกลับ) — ทำความสะอาดไฟล์ที่ไม่มีใครใช้ภายหลัง
- ย้ายแพ็กเกจข้ามกลุ่ม/หมวดยังไม่ได้ (หมวด/กลุ่มเป็นโครงสร้าง) ให้เพิ่มแพ็กเกจใหม่ในกลุ่มที่ต้องการแทน
