## วิธีใช้ (สำหรับ Admin)

1. เข้า `/admin` → **แก้ไขหน้าเว็บ** (หรือเปิด `/admin/editor` ตรง)
2. แถบด้านบน: เลือก **หน้า**, **ภาษา** ของตัวอย่าง (ไทย/English), **ขนาดจอ** (เดสก์ท็อป/แท็บเล็ต/มือถือ — ถ้าจอเล็กกว่าจะย่อให้พอดีและบอก %), **เต็มจอ**, โหมด **แก้ไข / ดูหน้าเว็บ**, และ **ตั้งค่าทั้งเว็บ** (header, เมนู, footer, ช่องทางติดต่อ, ข้อความของระบบ, SEO, สีของเว็บ)
3. โหมด **แก้ไข**: ชี้เมาส์ที่หน้าจะเห็นกรอบประ คลิกแล้วกรอบเป็นเส้นทึบพร้อมชื่อช่อง แผงด้านขวาเปิดส่วนที่มีช่องนั้นและพร้อมพิมพ์ทันที ช่องข้อความมีทั้งภาษาไทยและอังกฤษ (ภาษาที่แสดงในตัวอย่างตัวหนาพร้อมจุดสีน้ำเงิน)
4. ส่วนที่ซ้อนกัน (เช่น รายการคำถาม, เมนูย่อย) เปิดด้วยปุ่ม “›” และกลับด้วยแถบตำแหน่งด้านบนของแผง
5. ช่องที่ต่างจากฉบับเผยแพร่มีปุ่ม **คืนค่าที่เผยแพร่**; ทั้งเอกสารมีปุ่ม **ทิ้งร่างของเอกสารนี้**
6. สถานะมุมขวาบน: “มีการแก้ไข” → “กำลังบันทึก…” → “บันทึกแล้ว HH:MM น.” (ขึ้นเมื่อ server ยืนยันเท่านั้น) / “มีช่องที่ต้องแก้ก่อนบันทึก” (ช่องที่ผิดเป็นสีแดงพร้อมเหตุผล) / “บันทึกไม่สำเร็จ” (มีปุ่มลองอีกครั้ง) / “มีคนแก้พร้อมกัน” ปุ่ม **ร่างที่ยังไม่เผยแพร่ (N)** แสดงเอกสารที่มีร่าง
7. โหมด **ดูหน้าเว็บ**: หน้าเหมือนที่ผู้เข้าชมเห็น (รวมโมเดล 3D) กดลิงก์ในเว็บเพื่อเปลี่ยนหน้าใน editor ได้ ส่วนลิงก์ LINE โทร อีเมล และเว็บอื่นจะไม่เปิดจริง ระบบบอกปลายทางแทน และฟอร์มไม่ส่งจริง
8. ถ้าออกจากหน้าตอนที่ยังบันทึกไม่เสร็จ ระบบบันทึกทันทีหรือถามก่อนออก

## ความปลอดภัยและความถูกต้องของตัวอย่าง

- หน้า editor, หน้า preview และ Server Action ทุกตัวตรวจ session + สิทธิ์ Admin ที่ active จากฐานข้อมูลทุกครั้ง แล้วอ่าน/เขียนร่างด้วย session ของ Admin คนนั้นผ่าน RLS (ไม่ใช้ service role ใน app)
- ตัวอย่างเปิดใน iframe ของโดเมนเดียวกัน ข้อความระหว่าง editor กับตัวอย่างตรวจ origin, หน้าต่างต้นทาง, channel สุ่มต่อ session และ schema ของข้อความ (zod) ก่อนใช้
- ตัวอย่างไม่มี Google Ads tag และ Tawk, ไม่เปิดลิงก์ออกนอกเว็บ ไม่โทร ไม่เปิด LINE และไม่ส่งฟอร์ม; ถ้าเนื้อหาที่กำลังแก้ render ไม่ได้ ตัวอย่างคงหน้าล่าสุดที่แสดงได้พร้อมแจ้งเตือน
- การตอบกลับของหลังบ้านทั้งหมด `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow`, frame ได้เฉพาะจากเว็บตัวเอง
- ร่างผ่านการตรวจ 2 ชั้นก่อนถึงฐานข้อมูล: schema ของเอกสาร (ข้อความว่าง, ลิงก์, ตัวเลข, สี) และ reference ข้ามเอกสาร (รูป/สิทธิประโยชน์/แพ็กเกจที่อ้างถึงต้องมีจริง, แพ็กเกจเด่นต้องไม่ถูกซ่อน, ราคาปกติต้องสูงกว่าราคาเสนอ, ลิงก์ต้องไปหน้า/หมวดที่มีจริง); ฐานข้อมูลตรวจรูปแบบ id และขนาด (≤ 256 kB) ซ้ำอีกชั้น
- ลิงก์ที่หน้าเว็บเปิดจากเนื้อหาต้องเป็น `https://` บนโดเมนจริง (กันลิงก์ `javascript:` / `data:`) และ Admin แก้สคริปต์หรือรหัสการเชื่อมต่อจาก editor ไม่ได้
- ข้อความ error ทั้งหมดในหลังบ้านเป็นภาษาไทย

## สิ่งที่ทำ (เรียงตาม commit)

1. `refactor(site): render pages from a content context, with editor bindings and themes` — component หน้าเว็บรับเนื้อหาเป็นข้อมูล (ไม่ import เอง) จึง render ได้ทั้งฉบับเผยแพร่และร่าง; ทุกช่องมี binding ถาวร (`page:home/faq/items/<id>/answer`) ที่แสดงเฉพาะใน editor; สีของเว็บและพื้นหลังต่อ section; ภาพหน้าเว็บจริงเทียบกับ M2 ตรงกัน 23/24 ภาพ (ต่างเฉพาะเฟรม 3D ที่ขยับ)
2. `feat(db): store Mirror editor drafts with RLS and revision checks` — ตาราง `content_drafts`, `save_content_draft` / `discard_content_draft` ที่รับ revision ที่คาดไว้และตอบ `PT409` (HTTP 409) เมื่อชนกัน, pgTAP 39 ข้อ
3. `feat(content): Thai validation messages and https-only links`
4. `feat(editor): Admin-only draft preview and draft Server Actions` — `/admin/preview/<ภาษา>/<หน้า>` และ `saveDraftAction` / `discardDraftAction`
5. `feat(editor): Mirror editor with a field panel, autosave and conflicts` — `/admin/editor`, แผงแก้ไขที่สร้างจาก schema, คลังสื่อ, สถานะ/ชนกัน/ทิ้งร่าง, tests
6. `docs: …` — รายงานนี้และการตัดสินใจใน DECISIONS.md
7. แก้หลังรีวิวตัวเอง: เอกสารที่ถูกปฏิเสธเพราะติดเอกสารอื่นจะบันทึกเองเมื่อเอกสารนั้นแก้แล้ว (`fix(editor): save a document again…`), editor เปิดแบบอ่านอย่างเดียวพร้อมคำอธิบายเมื่อฐานข้อมูลยังไม่มีตารางร่าง (`fix(editor): open read-only…`), และ e2e บล็อก request ที่ออกนอกเว็บ (Google Ads, Tawk) เพราะ CI ล้มจากการรอสคริปต์ภายนอกเกิน 30 วินาที (`test(e2e): keep third-party scripts out…`)

## สิ่งที่เจ้าของต้องทำหรือตัดสิน

1. **Apply migration ของ M3 ที่ dev project** (session นี้เข้า Supabase ที่ host ไม่ได้): จากเครื่องที่ตั้งค่าไว้ตาม M1 รัน `npm run db:push:dev` (dry run — ต้องเห็น `20260930160641_content_drafts.sql` เป็นรายการเดียวที่จะ apply ที่ `wdcbbjvxrcxuaabcipqo`) แล้วรัน `npm run db:push:dev:apply` ถ้ายังไม่ apply หน้า editor ยังเปิดได้ (แสดงฉบับที่เผยแพร่) แต่ขึ้นแถบแดงว่าฐานข้อมูลยังไม่มีตารางร่าง และการแก้จะขึ้น “บันทึกไม่สำเร็จ” พร้อมชื่อ migration ที่ต้อง apply (ทดสอบแล้วกับ local stack ที่ซ่อนตารางไว้)
2. **จำนวนและลำดับของรายการ** (คำถามที่ยังเปิดใน ARCHITECTURE.md §3): ตอนนี้เพิ่ม/ลบ/เรียงได้เฉพาะ “บรรทัดข้อความ” (รายละเอียด เงื่อนไข หมายเหตุ ย่อหน้า) ส่วนคำถามที่พบบ่อย เมนู การ์ดบริการ ขั้นตอน ลิงก์ footer และแพ็กเกจเด่นแก้ค่าได้ทุกช่องแต่เพิ่ม/ลบไม่ได้ ถ้าต้องการเพิ่มคำถาม FAQ หรือเมนูเองให้แจ้ง จะเปิดทีละรายการพร้อมกติกา (เช่น FAQ ไม่เกินกี่ข้อ)
3. **อัปโหลดรูปใหม่** ต้องเปิด Supabase Storage (bucket + RLS + ตรวจชนิด/ขนาดไฟล์) — เสนอทำใน M4 พร้อม media usage ตอนนี้เลือกได้จากรูปที่นำเข้าจากเว็บเดิม
4. **การเผยแพร่** (ร่าง → หน้าเว็บจริง), ประวัติ และย้อนกลับ เป็น M4 ตามแผน ตอนนี้ร่างเห็นเฉพาะใน editor
5. ราคา/เงื่อนไขแพ็กเกจยังเป็นข้อมูลนำเข้าที่ **ยังไม่ยืนยัน** (ตาม M2) editor แสดงคำเตือนบนทุกแพ็กเกจที่ยังไม่ยืนยัน และเปลี่ยนสถานะเป็น “ธุรกิจยืนยันแล้ว” ได้เมื่อธุรกิจตรวจ

## ยังไม่รวมและข้อจำกัดที่ทราบ

- **ฉบับที่เผยแพร่ยังอยู่ใน repo** (`src/content`, ตรวจตอน build) ส่วนร่างของ Admin อยู่ใน Supabase ขั้น M4 จะเพิ่ม release ที่ตรึงทุกเอกสารใน Supabase ให้หน้าเว็บอ่าน และให้ปุ่มเผยแพร่ย้ายร่างขึ้นหน้าเว็บจริง

- editor ออกแบบสำหรับจอคอมพิวเตอร์ (กว้าง ≥ 1024 px แผงอยู่ด้านขวา) บนแท็บเล็ต/มือถือใช้ได้แต่แผงอยู่ใต้ตัวอย่าง
- ถ้า Admin อีกคนบันทึกเอกสารที่เราไม่ได้แก้ ตัวอย่างของเราไม่อัปเดตเองจนกว่าจะรีโหลด (การชนกันยังถูกจับตอนบันทึกเสมอ)
- ร่างที่บันทึกไม่ได้ (เช่น ช่องว่าง) อยู่ในหน้าจอจนกว่าจะแก้ ถ้าปิดหน้าก่อน ระบบถามยืนยันก่อนออก
- เลือก “ช่อง” บนหน้าด้วยคีย์บอร์ดได้ผ่านแผง (ทุกช่องเข้าถึงได้จากแผง) ส่วนการคลิกบนตัวอย่างใช้เมาส์/ทัช
- ตัวอย่างแสดงเฉพาะหน้าที่มีอยู่ ยังไม่มีการเพิ่มหน้าใหม่ (ตามขอบเขต fixed layout)
- Vercel preview ต้องมีค่า `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` ของ dev project จึงจะใช้หลังบ้านได้ (ตั้งค่าที่ Vercel ไม่ได้อยู่ใน repo)

## วิธีตรวจซ้ำ

```bash
npm ci
npm run lint && npm run typecheck && npm test && npm run build
npm run db:start              # Docker; ใน Claude Cloud รัน bash scripts/cloud/supabase-images.sh ก่อน
npm run db:test               # RLS/สิทธิ์ของร่าง
npm run test:e2e:local        # build กับ local stack แล้วรัน Playwright ทั้งหมด (รวม editor)
```

ทดลองใช้กับ dev project (หลัง apply migration ในข้อ 1 ของ “สิ่งที่เจ้าของต้องทำ”): ใช้ `.env.local` ชุดเดียวกับที่ทดสอบหลังบ้านใน M1 แล้ว `npm run dev` เปิด `http://localhost:3000/admin/editor` ด้วยบัญชี Admin ที่มีอยู่ ร่างที่บันทึกจะอยู่ในตาราง `content_drafts` ของ dev project และหน้าเว็บ `http://localhost:3000/` ยังแสดงฉบับเดิม
