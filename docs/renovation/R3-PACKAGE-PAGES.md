# R3 — หน้าแพ็กเกจ: กรอง เรียง เทียบ และหน้ารายละเอียด

วันที่ 1 ตุลาคม 2026 · ส่วนที่สามของงานออกแบบใหม่ ต่อจาก [R2-HOME-PROMOS.md](R2-HOME-PROMOS.md): หน้าแพ็กเกจ `/broadband`, `/broadband-old`, `/monthy`, `/topup` แนวเดียวกับ true.th/true-online แต่ใช้ง่ายกว่า — กรองตามความเร็ว ราคา และสิทธิประโยชน์ เรียงลำดับ เลือกเทียบ 2–3 แพ็กเกจ และหน้ารายละเอียดของแต่ละแพ็กเกจพร้อมปุ่มติดต่อ

## สิ่งที่ได้

- **กล่องค้นหาแพ็กเกจ** ใต้ส่วนเปิดหน้าของทุกหน้าแพ็กเกจ (`src/components/site/explorer/PackageExplorer.tsx`)
  - ความเร็ว: ปุ่มตามความเร็วดาวน์โหลดที่มีในหน้า (เช่น 500 Mbps / 700 Mbps / 1 Gbps / 1.5 Gbps) มีเฉพาะหน้าที่แพ็กเกจต่างความเร็วกัน
  - ราคาไม่เกิน: ตัวเลือกราคากลมๆ ที่แต่ละขั้นเพิ่มจำนวนแพ็กเกจจริง (ไม่มีขั้นที่ไม่เปลี่ยนอะไร)
  - มีสิทธิประโยชน์: เฉพาะสิทธิประโยชน์ที่บางแพ็กเกจมีและบางแพ็กเกจไม่มี
  - เรียงตาม: แนะนำ (ลำดับเดิมในหน้า), ราคาต่ำไปสูง, ราคาสูงไปต่ำ, เร็วที่สุดก่อน (เมื่อมีความเร็ว)
  - บอกจำนวน "แสดง X จาก Y แพ็กเกจ" (ประกาศให้โปรแกรมอ่านหน้าจอ) และปุ่มล้างตัวกรอง
  - หมวดที่ไม่เหลือแพ็กเกจแสดงข้อความ "ไม่มีแพ็กเกจในหมวดนี้ที่ตรงกับตัวกรอง" หมวดยังอยู่ anchor เดิม (`#internetpure`, `#cctv` …) จึงยังใช้ได้
- **เปรียบเทียบ**: ช่อง "เปรียบเทียบ" บนการ์ดทุกใบ เลือกได้ 3 ใบ แถบด้านล่างจอบอกจำนวนที่เลือก ปุ่มเปิดตารางเปรียบเทียบ (dialog) แสดงราคา ความเร็ว สัญญา/ระยะเวลา การใช้งาน สิทธิประโยชน์ เงื่อนไข รหัสกด และปุ่มสนใจ/ดูรายละเอียดของแต่ละแพ็กเกจ ปิดด้วยปุ่มปิดหรือ Esc
- **หน้ารายละเอียดแพ็กเกจ** `/packages/<รหัส>` (อังกฤษ `/en/packages/<รหัส>`) สร้างแบบ static ทุกแพ็กเกจที่แสดงบนเว็บ (80 หน้า × 2 ภาษา) อยู่ใน sitemap
  - แถบตำแหน่งหน้า (หน้าแรก / หน้าแพ็กเกจ / ชื่อแพ็กเกจ) ลิงก์กลับไปหมวดเดิม
  - ความเร็ว ราคา การใช้งาน สัญญา/ระยะเวลา รหัสกดสมัคร
  - กล่องติดต่อ: ปุ่มของหน้าแพ็กเกจนั้น ("สนใจแพ็กเกจนี้" → LINE ฝ่ายขาย ตามที่ตั้งไว้) และ "โทรหาฝ่ายขาย" — ฟอร์มขอให้ติดต่อกลับจริงจะมาใน M5
  - สิทธิประโยชน์พร้อมไอคอน รายละเอียด เงื่อนไข และรูป (รูปของแพ็กเกจเอง หรือรูปที่การ์ดโปรหน้าแรกใช้)
  - หมายเหตุท้ายหน้า: แพ็กเกจที่ราคายังไม่ยืนยันแสดง "ราคาและเงื่อนไขมาจากข้อมูลเดิมของร้าน อาจไม่ใช่ข้อมูลล่าสุด กรุณายืนยันกับเจ้าหน้าที่ก่อนสมัคร" ตามด้วยหมายเหตุของหมวดที่แพ็กเกจอยู่ (ข้อความเดิมของหน้าแพ็กเกจ เช่น ราคาไม่รวม VAT)
  - แพ็กเกจที่ซ่อนและรหัสที่ไม่มีได้หน้า 404 สองภาษา
- การ์ดทุกใบมีลิงก์ "ดูรายละเอียด" ไปหน้ารายละเอียด รวมการ์ดโปรในหน้าแรก (R2) และการ์ดในหน้าโซลาร์

## ราคาและหมายเหตุ

- ไม่มีการแก้ราคา เงื่อนไข หรือ review notes ในข้อมูล ทุกตัวเลขมาจาก catalog ตามเดิม
- หมายเหตุของหมวดในหน้าแพ็กเกจยังอยู่ที่เดิม และตามไปหน้ารายละเอียดด้วย
- ตารางเปรียบเทียบแสดงหมายเหตุราคายังไม่ยืนยันเมื่อมีแพ็กเกจที่ยังไม่ยืนยัน

## แก้ใน Mirror editor

- ข้อความใหม่ทั้งหมดอยู่ใน `site.ui` (ตั้งค่าทั้งเว็บ › ข้อความในเว็บ) มีทั้ง th/en: `findPackage`, `filterSpeed`, `filterPrice`, `filterBenefit`, `filterAny`, `sortBy`, `sortRecommended`, `sortPriceLow`, `sortPriceHigh`, `sortSpeed`, `resultCount` (ใส่ `{shown}` และ `{total}` ไว้ในข้อความ), `clearFilters`, `noMatches`, `compareAdd`, `compareChosen` (`{count}`), `compareOpen`, `compareMore`, `compareLimit`, `compareClear`, `close`, `breadcrumb`, `homeLink`, `unverifiedNote`, `packageContactNote`, `callSales`
- เนื้อหาหน้ารายละเอียดมาจากเอกสารแพ็กเกจ (`package:<รหัส>`) ที่แก้ได้ใน editor อยู่แล้ว ปุ่มสนใจมาจาก `packageCta` ของหน้าแพ็กเกจ หมายเหตุมาจาก `notes` ของหมวด
- ตัวกรองคำนวณจากข้อมูลเอง ไม่มีค่าให้ตั้ง (ความเร็ว ขั้นราคา สิทธิประโยชน์ที่ใช้กรอง)
- editor ยังไม่มีตัวอย่างของหน้ารายละเอียดแพ็กเกจ (ตัวอย่างมีเฉพาะหน้าที่เป็นเอกสารหน้า) ลิงก์ไปหน้ารายละเอียดในโหมดดูหน้าเว็บของ editor จะแจ้งว่าเปิดนอกตัวอย่าง

## ทำงานอย่างไร

- Server render ทุกแพ็กเกจเหมือนเดิม (anchor, SEO, ไม่มี JavaScript ได้ครบ) แล้ว `PackageExplorer` (client) ถือสถานะตัวกรอง/การเรียง/ที่เลือกเทียบใน React context การ์ด กลุ่ม และหมวด (`ExplorableCard`, `ExplorableGroup`, `NoMatches`, `ComparePick`) อ่าน context เพื่อซ่อนตัว เปลี่ยนลำดับ (CSS `order`) หรือแสดงข้อความ ไม่ยุ่ง DOM เอง นอกหน้าแพ็กเกจ (เช่น หน้าโซลาร์) ไม่มี context การ์ดจึงแสดงตามปกติและไม่มีช่องเปรียบเทียบ
- ตรรกะกรอง/เรียงเป็นฟังก์ชันบริสุทธิ์ใน `src/lib/content/package-facts.ts` (unit test) ข้อมูลตารางเปรียบเทียบเตรียมฝั่ง server เป็นภาษาของหน้า (`explorer-data.ts`)
- ไม่มี JavaScript (`@media (scripting: none)`) ซ่อนกล่องค้นหาและช่องเปรียบเทียบ เหลือทุกแพ็กเกจเรียงตามเดิม
- `next start` จะบันทึก `Error: Internal: NoFallbackError` เมื่อมีคนเปิด `/packages/<รหัสที่ไม่มี>` เพราะหน้าสร้างแบบ static ทั้งหมด (`dynamicParams = false`) — ผู้ชมได้หน้า 404 ตามปกติ เป็น log ของ Next 16 ไม่ใช่ข้อผิดพลาดของเว็บ

## ทดสอบ

- E2E ใหม่ `tests/e2e/package-pages.spec.ts` (desktop + มือถือ): ตัวกรองความเร็ว/ราคา/สิทธิประโยชน์ เหลือเฉพาะที่ตรงและล้างได้, การเรียงเปลี่ยนลำดับบนจอ, หมวดที่ว่างแสดงข้อความและ anchor ยังอยู่, เทียบ 2–3 แพ็กเกจและเกิน 3 ไม่ได้ ตารางมีชื่อ/ราคา/ลิงก์ถูก ปิดด้วย Esc, หน้ารายละเอียดจากลิงก์บนการ์ด (ชื่อ ราคา แถบตำแหน่ง หมายเหตุ ปุ่ม LINE/โทร) ทั้งไทยและอังกฤษ, ทุกหน้ารายละเอียดตอบ 200 แพ็กเกจที่ซ่อนได้ 404 และ sitemap มีหน้ารายละเอียด, ไม่มี JavaScript แสดงทุกแพ็กเกจโดยไม่มีตัวกรอง
- E2E ปรับ: sitemap ใน `public-routes.spec.ts` นับหน้ารายละเอียดด้วย, ลิงก์ดูรายละเอียดของการ์ดโปรหน้าแรกไปหน้ารายละเอียด
- Unit ใหม่ `tests/unit/package-facts.test.ts`: เทียบความเร็วข้ามหน่วย, ขั้นราคาที่เปลี่ยนผลจริง, สิทธิประโยชน์ที่ใช้กรองได้, การกรองและการเรียง (เสมอกันคงลำดับเดิม)
- เทสต์เดิมผ่านครบ: URL และ anchor เดิม, ปุ่ม LINE, editor (รวมเทียบภาพ editor/public ของ `/en/broadband` ที่มีกล่องค้นหาแล้ว)

## ข้อจำกัดและงานต่อ

- ตัวกรองไม่จำในลิงก์ (รีโหลดแล้วเริ่มใหม่) ถ้าต้องการแชร์ลิงก์ที่กรองแล้วค่อยเพิ่มภายหลัง
- หน้ารายละเอียดยังไม่มีรายการ "แพ็กเกจที่คล้ายกัน"
- ปุ่มติดต่อในหน้ารายละเอียดยังเป็น LINE/โทร จนกว่า M5 จะมีฟอร์มขอให้ติดต่อกลับ
- R4 (CRUD สินค้าและบริการ + อัปโหลดรูป) ยังไม่เริ่ม
