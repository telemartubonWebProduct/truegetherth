# M5 — ฟอร์มขอให้ติดต่อกลับ, consent คุกกี้ และ GA4

วันที่ 2 ตุลาคม 2026 · ตาม prompt 10 และคำตอบของเจ้าของใน [R4-M4-M5-PROPOSAL.md](R4-M4-M5-PROPOSAL.md): มี GA4 property แล้ว (Measurement ID `G-DQGCC5J4YM` ส่งมา 2 ต.ค.), แจ้งเตือนทีมขาย **ในหลังบ้านอย่างเดียว**, เก็บข้อมูลผู้ติดต่อ **1 ปีหลังปิดคำขอ** แล้วลบ/ทำให้ระบุตัวตนไม่ได้

## สิ่งที่ได้

### หน้าเว็บ

- **ฟอร์มขอให้ติดต่อกลับ** ในหน้าติดต่อเรา (`/service#callback`, `/en/service#callback`) แทนแถบ "ส่งข้อมูลทาง LINE" เดิม: ชื่อ, เบอร์โทร (รับ 081-234-5678 / +66… แล้วแปลงเป็น 0XXXXXXXXX), จังหวัด (77 จังหวัด รหัส ISO 3166-2:TH), อำเภอหรือรหัสไปรษณีย์ (ไม่บังคับ), บริการ (เน็ตบ้าน/มือถือ/โซลาร์/อื่นๆ), ช่วงเวลาที่สะดวก, รายละเอียด (ไม่บังคับ) และติ๊กยินยอมตามนโยบายความเป็นส่วนตัว รับเรื่องทุกจังหวัด ไม่อ้างว่าติดตั้งได้ทุกที่
- **ตรวจข้อมูล** ทั้งในเบราว์เซอร์ (ตอบทันที ข้อความผิดอยู่ใต้ช่อง และย้ายโฟกัสไปช่องแรกที่ผิด) และที่ server (Server Action ตรวจซ้ำด้วยกฎชุดเดียวกัน `src/lib/leads/form.ts`) แล้วฐานข้อมูลตรวจอีกชั้นด้วย check constraint
- **กันส่งซ้ำ**: ฟอร์มแต่ละครั้งมี idempotency key กดส่งซ้ำ/ดับเบิลคลิกได้คำขอเดียว; คำขอใหม่จากเบอร์เดิมสำหรับบริการเดิมขณะคำขอเดิมยังไม่ปิด จะต่อท้ายประวัติของคำขอเดิม (ป้าย "ส่งซ้ำ") ไม่เพิ่มคำขอ
- **กันสแปม**: honeypot (ช่องซ่อนที่คนไม่เห็น บอตที่กรอกจะเห็นว่าส่งสำเร็จแต่ไม่มีอะไรถูกเก็บ), จำกัด 5 คำขอต่อผู้ส่ง (HMAC ของ IP, ไม่เก็บ IP จริง) ต่อ 10 นาที และ 300 คำขอต่อชั่วโมงทั้งเว็บ; ไม่มี Turnstile (เพิ่มได้ถ้าสแปมมาก)
- **สำเร็จจริงเท่านั้น**: ข้อความ "ได้รับคำขอแล้ว" แสดงหลังฐานข้อมูลบันทึกแล้วเท่านั้น ถ้าส่งไม่สำเร็จหรือถูกจำกัด จะบอกให้ลองใหม่หรือทัก LINE/โทร
- **มาจากหน้าแพ็กเกจ**: หน้ารายละเอียดแพ็กเกจมีปุ่ม "ขอให้เจ้าหน้าที่โทรกลับ" ไปที่ `/service?package=<id>#callback` ฟอร์มใส่แพ็กเกจและบริการให้ (เอาออกได้)
- ถ้า deployment ยังไม่มี `SUPABASE_SECRET_KEY` หน้าติดต่อเราแสดงข้อความให้ทัก LINE/โทรแทนฟอร์ม (ไม่มีฟอร์มที่ส่งไม่ได้)
- ข้อความทุกคำ (ป้าย คำอธิบาย ข้อความผิดพลาด ข้อความสำเร็จ) อยู่ใน `site.leadForm` แก้ได้ทั้งไทย/อังกฤษใน Mirror editor (ฟอร์มแสดงในตัวอย่างแต่ไม่ส่ง)
- นโยบายความเป็นส่วนตัว (หัวข้อ 7 และ 8) เพิ่มย่อหน้าว่าฟอร์มเก็บอะไร ใช้ทำอะไร เก็บนานเท่าไร และคุกกี้ใช้หลังยินยอม — **ข้อความนโยบายทั้งหมดยังต้องให้ธุรกิจ/ที่ปรึกษากฎหมายตรวจ**

### Consent คุกกี้ (PDPA)

- แถบคุกกี้แสดงจนกว่าผู้ชมจะเลือก: "ยอมรับทั้งหมด", "ใช้เฉพาะที่จำเป็น" (ง่ายเท่ากัน) หรือ "เลือกเอง" แยก 3 กลุ่ม: วิเคราะห์การใช้งาน (GA4), โฆษณา (Google Ads), แชตสด (Tawk)
- ก่อนเลือก ไม่มี gtag.js ไม่มี Tawk ไม่มีคุกกี้ของบุคคลที่สาม; หลังเลือกโหลดเฉพาะที่ยินยอม และตั้ง Google consent mode (`analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization`) ตามที่เลือก
- "ตั้งค่าคุกกี้" ท้ายทุกหน้าเปิดแถบอีกครั้ง ถอนความยินยอมได้ (หน้าโหลดใหม่ ลบคุกกี้ `_ga`/`_gcl` ของเว็บ)
- เก็บการเลือกในคุกกี้ `tm_consent` 180 วัน พร้อมรุ่นของนโยบาย (`site.consent.policyVersion`, ตอนนี้ `2026-10-02`) เปลี่ยนวันที่นี้เมื่อแก้นโยบาย ผู้ชมทุกคนจะถูกถามใหม่; คำขอแต่ละรายการบันทึกรุ่นนโยบายที่ยินยอมไว้ด้วย
- **ผลต่อ conversion ของ Google Ads ที่คืนใน prompt 1**: ตอนนี้ยิงเฉพาะผู้ชมที่ยินยอมกลุ่มโฆษณา (และบนโดเมนจริงเท่านั้นเหมือนเดิม) ตัวเลข conversion จะน้อยกว่าเว็บเดิม

### GA4 events (เฉพาะโดเมนจริง และเฉพาะผู้ชมที่ยินยอมกลุ่มวิเคราะห์)

| event | เกิดเมื่อ | พารามิเตอร์ |
| --- | --- | --- |
| `contact_line` | คลิกลิงก์ LINE ใดๆ | `cta_id` (รหัสปุ่มคงที่), `page_path` |
| `contact_phone` | คลิกโทรหาทีม (ไม่นับรหัสกดสมัคร *…#) | `cta_id`, `page_path` |
| `contact_email`, `contact_facebook` | คลิกอีเมล / เฟซบุ๊ก | `cta_id`, `page_path` |
| `lead_form_start` | เริ่มกรอกฟอร์ม | `form_id` |
| `generate_lead` | ฐานข้อมูลบันทึกคำขอใหม่แล้ว (ไม่นับคำขอซ้ำ) | `form_id`, `lead_service`, `package_id` |

แยกชื่อ event ตามช่องทาง (แทน `contact_click` + พารามิเตอร์ใน ARCHITECTURE.md) เพื่อให้เห็นในรายงาน Events ทันทีและตั้งเป็น key event แยกกันได้ ไม่ส่งชื่อ เบอร์ พื้นที่ หรือข้อความที่กรอกไป GA4

### หลังบ้าน

- **คำขอติดต่อกลับ** (`/admin/leads`): ใหม่สุดก่อน กรองสถานะ/บริการ ค้นชื่อหรือเบอร์ เมนูแสดงจำนวนคำขอใหม่ (นี่คือการแจ้งเตือนตามที่เจ้าของเลือก) และดาวน์โหลด CSV (เปิดใน Excel ภาษาไทยได้, กันสูตรใน cell, ทุกการดาวน์โหลดบันทึกใน audit log)
- **หน้าคำขอ** (`/admin/leads/<id>`): ข้อมูลที่ส่งมา แพ็กเกจ หน้าที่ส่ง แคมเปญ (utm) รุ่นนโยบาย; เปลี่ยนสถานะ (ใหม่ → รอติดต่อ → ติดต่อแล้ว → ปิดคำขอ ซึ่งต้องเลือกผล), ผลตรวจพื้นที่, วันนัดติดตาม, บันทึกการติดตาม; ประวัติทุกการเปลี่ยนพร้อมผู้แก้และเวลา; ถ้ามีคนแก้หลังเปิดหน้า ระบบปฏิเสธไม่ให้ทับ
- **ลบข้อมูลส่วนบุคคล** ของคำขอทันทีเมื่อเจ้าของข้อมูลขอหรือเป็นสแปม (ยืนยันก่อน, บันทึก audit) เหลือเฉพาะจังหวัด บริการ วันที่ สถานะ สำหรับรายงาน
- **รายงาน** (`/admin/reports`): ช่วง 7/30/90 วัน/1 ปี ตามเวลาไทย: คำขอที่ได้รับ ติดต่อได้ สมัครแล้ว คำขอรายวัน สถานะ บริการ จังหวัด แพ็กเกจ แคมเปญ หน้าที่ส่ง และการเผยแพร่หน้าเว็บในช่วงนั้น; ส่วน GA4 บอกว่าส่ง event อะไร ไปที่ไหน ดูที่ใดใน GA4 และ **ยังไม่ดึงตัวเลขจาก GA4 Data API** (ไม่แสดง 0 หลอก)

## สิ่งที่พบระหว่างทำ

- Mirror editor เรนเดอร์ component หน้าเว็บในเบราว์เซอร์ด้วย (ตัวอย่างสด) จึงห้าม import โมดูล server-only ใน `src/components/site` — สถานะ "ฟอร์มส่งได้ไหม" ส่งเข้ามาทาง `RenderContext.leads` จาก route ของหน้าเว็บ
- Server Action ตรวจ Origin กับ host; เทสต์ที่จำลองโดเมนจริง (`serveAt`) จึงส่ง `x-forwarded-host` เหมือน proxy
- data cache ของ Next (`.next/cache/fetch-cache`) อยู่ข้าม build: เทสต์ M4 ที่ลบ release ตรงในฐานข้อมูลทิ้ง release เก่าไว้ใน cache สคริปต์ e2e จึงล้าง fetch cache ก่อน build และ fetch ของเนื้อหาที่เผยแพร่มีอายุสูงสุด 1 วัน (ถ้าฐานข้อมูลถูกเปลี่ยนนอกหลังบ้าน เช่น restore backup หน้าเว็บตามทันภายในวัน)

## ข้อจำกัดและงานต่อ

- แจ้งเตือนภายนอก (อีเมล/LINE OA) ยังไม่มีตามที่เลือก เมื่อจะเพิ่ม: ตาราง outbox + งานส่งที่ retry ได้ โดยคำขอถูกบันทึกก่อนเสมอ (ล้มเหลวไม่ทำคำขอหาย)
- GA4 Data API (ตัวเลขผู้ชม/คลิกในหน้ารายงาน): ต้องมี GA4 **Property ID** (ตัวเลข) และ service account ที่ได้สิทธิ์ Viewer บน property จากเจ้าของ — เป็นงาน integration ที่เหลือ
- ใน GA4 ให้เจ้าของตั้ง `generate_lead`, `contact_line`, `contact_phone` เป็น key event และลงทะเบียน custom dimension `cta_id`, `form_id`, `lead_service`, `package_id` (event scope) ถ้าต้องการแยกรายงานตามปุ่ม/บริการ
- คำขอที่ยังไม่ปิดไม่ถูกลบอัตโนมัติ ทีมควรปิดคำขอที่จบแล้ว; ถ้าต้องการลบคำขอค้างนานด้วย ให้ตัดสินระยะเวลา
- ข้อความนโยบายความเป็นส่วนตัวและแถบคุกกี้ต้องให้ธุรกิจ/ที่ปรึกษากฎหมายตรวจก่อนเปิดใช้จริง
