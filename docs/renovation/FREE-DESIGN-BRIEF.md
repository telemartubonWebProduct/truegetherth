# Free design brief — Telemart Ubon

วันที่ 29 กันยายน 2026: **brief ด้านล่างเขียนใหม่สำหรับธุรกิจ Telemart** ไม่ได้ดึงหรือถอดข้อความ Premium ของ Minimal Workflow SaaS, SaaS Pricing Flow หรือ NEX Robotics ทั้งสามแบบยังเป็นเพียงภาพอ้างอิงสาธารณะของแนวทาง A+B+C ที่ผู้ใช้เลือก

งานหลักตรวจ `get_prompt` ของ **[Rocket Pricing](https://motionsites.ai/?prompt=rocket-pricing)** แล้วได้ prompt เต็มที่เปิดอ่านได้ฟรี จึงใช้เป็น reference ของการเปรียบเทียบแพ็กเกจ การ์ดเด่น และลำดับข้อมูลราคา โดยปรับเป็นธุรกิจเน็ตไทยและ stack ของโปรเจกต์ ไม่ใช้ React 18/Vite หรือธีมมืดจากตัวอย่างมาแทนข้อสรุปของงานนี้ ไม่มีการซื้อ prompt หรือ subscription

## Prompt ต้นฉบับสำหรับออกแบบและสร้างตามแผน

ออกแบบเว็บ Telemart Ubon ใหม่ให้เป็นเว็บไซต์โปรโมทแพ็กเกจเน็ตบ้านทรู เน็ตมือถือ และบริการโซลาร์เซลล์ W&W Energy สำหรับผู้สนใจทั่วประเทศ จุดหมายหลักคือให้ลูกค้าฝากข้อมูลเพื่อเจ้าหน้าที่ติดต่อกลับ พร้อมช่องทาง LINE และโทรศัพท์ที่ตรวจแล้ว การส่งคำขอสำเร็จเป็นคนละเหตุการณ์กับการคลิกติดต่อ ไม่ต้องมี checkout หรือชำระเงินในขอบเขตนี้

รักษาทิศทางที่ตกลงไว้: หน้าเปิดสะอาดแบบ A, การเปรียบเทียบแพ็กเกจอ่านง่ายแบบ B และภาพเทคโนโลยีขนาดใหญ่ที่จัดองค์ประกอบอย่างมีพื้นที่หายใจแบบ C ใช้ Rocket Pricing ที่เปิดอ่านได้ฟรีเป็น reference ของโครงข้อมูลราคา แล้วสร้างหน้าตาเฉพาะ Telemart จากข้อมูลธุรกิจจริง

**Art direction:** ขาวเป็นพื้นหลัก ดำเป็นตัวอักษรและพื้นที่เน้น แดงเป็นการกระทำสำคัญ ใช้ white-space และลำดับตัวอักษรสร้างความ premium ให้ภาพ Router Wi-Fi เป็นจุดเด่นเดียวของ hero สีตั้งต้นเป็น design tokens ของข้อเสนอนี้: white `#FFFFFF`, Telemart red `#E60012`, black `#000000`, soft surface `#F5F5F5`, secondary text `#52525B`, border `#E4E4E7` ผู้ดูแลเปลี่ยนค่าผ่าน settings ที่ตรวจ contrast ได้ เลือก IBM Plex Sans Thai เป็น family หลักสำหรับหัวเรื่องและเนื้อหา ปรับ weight/size ตามบทบาท ใช้ตัวเลขราคาและความเร็วที่อ่านเทียบกันง่าย

**หน้าแรก desktop:** วาง logo/เมนูสั้นในแถบขาว มีปุ่ม “ให้เจ้าหน้าที่ติดต่อกลับ” สีแดง ด้าน hero วางหัวเรื่องไทยกับข้อความช่วยเลือกบริการทางซ้าย และ Router Wi-Fi สีขาวมุม 3/4 ขนาดใหญ่ทางขวา ใช้แสง studio, ผิวพลาสติกและรายละเอียดขอบที่สมจริง พร้อมวงแหวน/เส้นสัญญาณแดงบาง ๆ ที่สื่อการเชื่อมต่อโดยไม่บดบังสินค้า ข้อความเสนอเริ่มต้นคือ “เลือกเน็ตบ้านที่เหมาะกับทุกวันของคุณ” และ CTA “ดูแพ็กเกจเน็ตบ้าน” กับ “ให้เจ้าหน้าที่ติดต่อกลับ” ข้อความเหล่านี้เป็น copy draft ที่แก้ได้

**ภาพ Router:** เป็น Router Wi-Fi ของทรู; SKU ยังไม่ยืนยัน ให้ใช้ product reference ที่อนุมัติก่อนสร้างรูปทรงจริง ระหว่างรอให้แสดงภาพ placeholder ที่ระบุสถานะในงาน preview หลีกเลี่ยงการอ้างรุ่นหรือคุณสมบัติที่ยังไม่มีข้อมูล ใช้ Three.js/Fiber/Drei ที่เตรียมแล้วเมื่อ interaction เพิ่มคุณค่า หรือใช้ render/cinematic media ที่คุณภาพดีกว่าได้ มี poster คุณภาพสูงก่อนโหลดฉาก และเลือกมุมกับ motion ให้เข้าใจอุปกรณ์โดยไม่แข่งกับหัวเรื่องและ CTA

**หน้าแรก mobile:** ข้อความและ CTA มาก่อน Router อยู่ถัดมา ไม่บังคับหมุนเครื่อง ไม่ให้ canvas จับ scroll ทั้งหน้า จัดราคาและข้อมูลสำคัญเป็นแนวตั้ง อ่านได้ด้วยมือเดียว มีปุ่มติดต่อที่มีพื้นที่กดชัดและไม่ทับข้อความ/ฟอร์ม รักษาองค์ประกอบขาว แดง ดำและสัดส่วนภาพเหมือน desktop

**ส่วนบริการ:** หลัง hero ให้ลูกค้าเลือกเน็ตบ้านลูกค้าใหม่, เน็ตบ้านลูกค้าปัจจุบัน, เน็ตมือถือ และโซลาร์เซลล์ด้วยข้อความตรงไปตรงมา คงความชัดเจนว่า W&W Energy เป็นบริการโซลาร์คนละหมวดกับทรู ไม่ทำให้ลูกค้าเข้าใจว่าแพ็กเกจหรือเงื่อนไขใช้ร่วมกัน

**ส่วนแพ็กเกจ:** ใช้การ์ดเปรียบเทียบที่เรียงหัวข้อเหมือนกัน: ชื่อแพ็กเกจ, เหมาะกับใคร, download/upload พร้อมหน่วย, ราคา/รอบบิล, VAT, สัญญา, สิทธิประโยชน์, เงื่อนไข และปุ่ม “สนใจแพ็กเกจนี้” ให้เห็นราคาและความเร็วชัดก่อนอ่านรายละเอียด ใช้ป้าย “แนะนำ” เฉพาะรายการที่ธุรกิจกำหนดจริง ปรับจำนวนคอลัมน์ตามข้อมูลและขนาดจอ โดยคง schema และ design system ใช้ข้อมูลแพ็กเกจที่ตรวจแล้วเท่านั้น อย่าสร้างราคา โปรโมชั่น รีวิว หรือยอดผู้ใช้งานขึ้นเอง

**ส่วนความมั่นใจและติดต่อ:** แสดงขั้นตอนสั้น “เลือกบริการ → ฝากข้อมูล → เจ้าหน้าที่ตรวจพื้นที่และติดต่อกลับ” ข้อความ nationwide ต้องสื่อว่าให้รับเรื่องจากทั่วประเทศ แต่การติดตั้งขึ้นอยู่กับการตรวจพื้นที่จริง ฟอร์ม lead แสดงบริการ/แพ็กเกจที่เลือกและข้อมูลที่จำเป็น ชื่อ เบอร์โทร พื้นที่ และหมายเหตุที่เลือกกรอกได้เป็นข้อเสนอเริ่มต้น รายละเอียด fields, consent และช่องทางแจ้งเตือนให้ใช้ผล interview ที่ตกลงก่อน implementation แสดงสถานะกำลังส่ง/ส่งสำเร็จ/ส่งไม่สำเร็จพร้อมวิธีทำต่อ

**โซลาร์เซลล์:** ทำพื้นที่ W&W Energy ที่แยกหมวดชัด ใช้ภาพหน้างาน/ผลิตภัณฑ์จริงและข้อมูลบริการที่ยืนยัน มี CTA “ขอคำปรึกษาโซลาร์เซลล์” ที่ส่งบริบทประเภทบริการไปกับ lead ให้แพ็กเกจและขั้นตอนสำรวจหน้างานอยู่ในหน้า solar โดยไม่แย่งจุดเด่นเน็ตบ้านของหน้าแรก

**หลังบ้าน:** ใช้ Admin role เดียวกับ Supabase Auth ของ project แยกสำหรับเว็บนี้ หลังบ้านมี Overview, Mirror Editor, แพ็กเกจ/บริการ, Media, Leads, Analytics/Reports และ Settings ชื่อเมนูและปุ่มเป็นภาษาที่แอดมินเข้าใจ เมื่อเปิด Mirror Editor เห็นหน้าเหมือน public ทุกขนาดจอ เปิด Edit mode แล้วคลิกข้อความ รูป ปุ่ม หรือพื้นหลังเพื่อเปลี่ยนค่าและเห็น draft เปลี่ยนทันที มี “บันทึกร่าง”, “เผยแพร่” และการคืน revision ที่ชัดเจน โครง layout และลำดับ sections คงที่ตามหน้าใหม่ที่ตกลง ไม่ทำ free-form page builder

**โครงสร้าง implementation:** ใช้ Next App Router/React target ที่วางแผนไว้ แยก content schema, shared PageRenderer/sections, editor controls, catalog, leads, analytics และ auth/data adapters หน้าบ้านและ Mirror Editor ต้องใช้ renderer กับ content contract เดียวกัน Public อ่าน published content; editor อ่าน draft ของ admin เท่านั้น ค่าที่มองเห็นได้ทั้งหมดผูกกับ field registry ที่ validate ได้ รวม nav/footer, text, image/poster/video, background, CTA, ราคา/เงื่อนไข, SEO และ theme ที่อนุมัติ สิทธิอ่าน/แก้ข้อมูลบังคับฝั่ง server/database ไม่อาศัยการซ่อนปุ่ม

**Motion และคุณภาพ:** ใช้ hero reveal สั้นหนึ่งครั้งและ motion ที่ตอบการกระทำของคนอ่าน ให้โมเดลพักได้ เคารพ reduced motion และลดคุณภาพ/ใช้ poster บนเครื่องที่ไม่เหมาะสม โหลด 3D เป็น client component แยกหลัง content พร้อม หลีกเลี่ยง motion ซ้ำทุก section, auto-carousel ที่ขัดการอ่าน และภาพ background ที่ทำให้ตัวอักษรอ่านยาก ตรวจ keyboard focus, touch targets, contrast, image alt, font/asset loading และการแก้ draft/publish จริงก่อนรับงาน

**สิ่งส่งมอบตามขั้น:** ทำ token/wireframe และ preview ที่ใช้ข้อมูล Telemart ให้ตรวจทิศทางก่อน จากนั้นสร้าง public/content renderer, Mirror Editor และหลังบ้านตาม milestone ที่อนุมัติ พร้อมทดสอบ mobile, auth/RLS, lead submission, analytics events และ publish/restore ส่วน hosting ใช้ Vercel กับโดเมนที่มีอยู่ การสร้าง Supabase project แยกยังต้องเลือก organization/ค่าใช้จ่ายตามขั้น setup ก่อนลงมือสร้าง resource
