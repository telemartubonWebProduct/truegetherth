## What the site is

Public pages collect contact-back leads from all of Thailand for True home internet and mobile packages, and keep W&W Energy solar. Thai is served at the old site's URLs (`/`, `/broadband`, `/monthy`, …), English under `/en`. Each language has its own root layout in a route group (`src/app/(th)`, `src/app/(en)`), so there is no rewrite (the old `[locale]` + rewrite broke RSC requests on Vercel). The page files in those folders are generated: edit `src/content/routes.ts` and `scripts/routes/generate.mjs`, then run `node scripts/routes/generate.mjs`. Shared layout and route helpers are in `src/app/_site`. `src/app/global-not-found.tsx` is the 404 for both languages. Preserve the old public URLs or add tested redirects; `tests/e2e/public-routes.spec.ts` covers them.

Pages render the validated content in `src/content` through `src/lib/content` with the components in `src/components/site`; every visible string needs both `th` and `en`. Public pages read the published release from Supabase and fall back to `src/content`. Content schema changes bump `CONTENT_SCHEMA_VERSION` (now 10: the catalog lists the packages recommended on the home page, a package can have days it shows on, a home tab names categories instead of cards, the site's words have the mark a recommended package's card carries, the contact details have the head office and hours, and the Ads conversion setting is `googleAdsLeadConversion`); a published release of another version is not shown until it is published again, and drafts of another version are skipped. Components in `src/components/site` also render in the editor's in-browser preview, so they must not import server-only modules; pass server facts in through `RenderContext`.

The back office (`/admin`, one invite-only Admin role): the Mirror editor (`src/components/editor`, `src/app/admin/(editor)`) mirrors the public page and edits every content, media, CTA and theme value in a fixed layout; it builds its fields from the content schema, so a new schema field needs a Thai label in `src/components/editor/labels.ts` (a unit test enforces it), and structural keys stay read-only. It keeps to the words, pictures, buttons and theme of each page. Packages are managed on a page of their own, "แพ็กเกจและโปร" (`/admin/catalog`, `src/components/catalog`, `docs/renovation/R7-CATALOG.md`): lists per category and group to add to, edit, copy, move, hide and remove from, several at once; the groups of each package page; the packages recommended on the home page; and the benefits. What ties it to the pages: a package shows on the page that lists its group, gets a card on the home page when it is recommended (the catalog document's `featured`; it then needs a picture), and only on its days (`showFrom`, `showUntil`; `isShown` in `src/lib/content/lookup.ts` is the one test of whether visitors see a package, with the day in Thailand passed in). The five categories are fixed, each a page of the site. A new package or a copy is named first and its English name becomes its id and address (`/packages/<id>`), which never changes; it starts hidden, a new one with no price. What each action does to the content is in `src/components/catalog/catalog-edit.ts`, as plain functions with unit tests. The page writes the same drafts as the editor (`DraftStore`). Publish/history/rollback, the lead inbox and the report are also under `src/app/admin/(console)`. The lead form stores requests with the server-only `SUPABASE_SECRET_KEY`; without it the contact page offers LINE and phone instead.

The site's one domain is `https://www.truegetherth.com` (`siteUrl()` in `src/lib/seo/metadata.ts`): canonical addresses, the sitemap and the share card name it, and Google Analytics and the Ads conversion count on that host only. A Google Ads conversion is a visitor asking to be contacted (a sent call-back form, a click on LINE or a phone number; `trackLeadConversion`), never the opening of a page. Every page carries structured data read from the content (`src/lib/seo/structured-data.ts`): who runs the site, the page's place in it, the home page's questions; it gives no price. The footer, the terms and that data say that the site is run by Telemart Communication Co., Ltd., an appointed partner and Authorized Dealer of True, and is not True's own site: keep that statement wherever the business is described.

## Look and motion

Package cards (`docs/renovation/R8-PROMO-CARDS.md`): on package pages a card is a slip (`PackageCompare.tsx`, `.tm-slip` in `globals.css`) led by what the package gives in figures, with its price on a stub under a perforation, and it needs no picture of its own; on the home page a card is a picture plate with the figure over the picture (`PackageCard` in `Landing.tsx`). What comes with a package is always shown with its picture, in a white tile of one size (`BenefitList`); where only the tiles show, the names stay in the page for screen readers.

Minimal black and white: white canvas, near-black ink (`#0b0b0c`) for text, buttons and dark sections, Inter (Latin, in two cuts made by `scripts/fonts/subset.py`: the one every page fetches holds weights 300 to 700 and the characters the site's own words use) and Anuphan (Thai) from `src/fonts` set light, pill buttons and a floating pill navigation on every page. Red is rationed to marks: prices, meters, the live step, the dot of a recommended package. What is in full colour is the painting that opens the home page and, in its manner, the four small pictures on the slip of the steps. Colours are theme tokens (`src/styles/tokens.css`, defaults in `src/lib/content/theme.ts`, editable in site settings with contrast checks); `src/app/globals.css` (Tailwind 3 plus shared classes) holds what every page shares, and `src/styles/landing.css` (plain CSS) the home page's stages, the navigation and the motion.

The home page (`src/components/site/home`, rendered by `Landing.tsx` from `pages.home`) is five pinned stages — hero, manifesto, the rail of recommended packages (a tab per category), the slip that prints the four steps (its picture changes with the step: four small paintings of the opening's figures, from `design/steps` by `node scripts/media/step-pictures.mjs`, decoration and not content, R11), services — then a price table and questions. `ScrollDriver.tsx` is the page's one scroll handler: it only writes custom properties on `<html>` and switches a few attributes; the CSS does the rest; Lenis smooths wheel scrolling and is fetched after the first paint. It measures first and writes after, every frame: a measurement after a write makes the browser work the whole page out again. The choreography applies only under `html[data-motion]`, set before first paint by the site layout when the visitor has not asked for reduced motion and the screen is at least 560px tall. Without it (no JavaScript, reduced motion, a short screen, and the editor's preview, which is locked flat) every section lies flat and fully visible. Keep that true for anything new: base styles are the flat layout, motion goes under `html[data-motion]`. Under it the stages below the opening are laid out only when they come near the screen (`content-visibility: auto`; their height is set, so nothing moves), which is why a script must not measure inside them while the page starts. The footer and the contact band are not: a section laid out on demand has a guessed box until then, and accessibility checkers read the wrong colour behind words beyond it. A pinned stage must fit one screen at any height (`node scripts/media/stage-sizes.mjs rail` checks nine sizes).

### The hero picture

The opening is an oil painting in layers (`docs/renovation/R6-HERO-TABLEAU.md`): a goddess lifts the True router over her head, with three cherubs, a sea god and a muse around her, each holding something that needs the internet.

- **The pictures** were generated by the owner (Nano Banana Pro) from the prompts in `design/hero/tableau/README.md` and are kept in `design/hero/tableau/source/`: the painting, its figures alone on green, its sky with nobody in it, and a bank of near cloud. All are derived from the one painting, so the layers agree.
- **The cutting** is `node scripts/media/hero-tableau.mjs` (`--debug` saves each cut-out and each arrangement laid flat to `shots/hero-tableau/`). It keys the green, splits the figures, and writes the skies, the layers and the True Online mark to `public/media/hero-v4/`, and where each layer sits to `src/components/site/home/hero-tableau.ts`. That file is generated: the numbers to change (place, depth, float, signal frames) are in the script's `PACKS`. There are two arrangements of the same figures: `wide`, as painted, covers a desktop screen; `tall` stands them upright above the headline on a phone or an upright tablet.
- **The page** (`Hero.tsx`, the hero part of `landing.css`) lays the sky and every figure as plain pictures, so the painting is whole without scripts, with reduced motion and in the editor. All of them are lazy and none is asked for ahead of the page. Under `html[data-motion]` the painting's box is dark from the first paint and the scene inside waits 0.4 s before it settles in, whole: a browser does not time what it first paints unseen, so the page's largest paint stays the headline, in the first frame (R10; take the wait out and the score depends on which picture arrives when). Each figure floats, the layers shift with the pointer and part as the page scrolls, and thin signal frames flicker on the figures. `hero.visual` is the sky; its description is of the whole picture.
- **The True logo is never generated.** The router is painted without one, and the mark on the router's frame is the owner's own file (`design/hero/router/trueonline.png`). Do not keep a generated picture that shows lettering or a logo on the router.
- The numbers on the signal frames are decoration. Nothing in the picture states a speed, a price or an offer.

A new picture goes in a new folder (`hero-v5`; `steps-v2` for the steps' pictures): browsers keep the files for a year, and the scripts refuse to change one in place (`--replace` is for a file that was never published). The rules of the painting hold for every generated picture: no lettering, no logo, nothing that states a speed, a price or an offer. The 3D router and the robot arm of the first hero are gone from the site; `design/hero/README.md` and `scripts/blender/router.py` keep how they were made.

## Working here

Node 24.18.0 (`.nvmrc`); `package-lock.json` is authoritative. Next 16.4.0 with React 19.3: this version has breaking changes against older Next.js, so read the relevant guide in `node_modules/next/dist/docs/` before using an API you have not used in this version, and heed deprecation notices.

- `npm run dev -- --port 3200` (port 3000 belongs to another app of the owner's on this machine).
- Checks: `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run build`.
- Speed: what a visitor on a slow phone sees first must not wait for script. The opening's entrance is CSS under `html[data-motion]` and leaves the headline out; the cookie banner is in the page's HTML; a client component of a public page must not import a module that brings the schema's validation library (`src/lib/leads/fields.ts` is the form's library-free half). PageSpeed counts everything a page has fetched and run by its largest paint (R10), so before the first paint a page fetches its HTML, its stylesheets and two fonts, and nothing else: no picture asked for ahead of the page, no animation library (the menu's panel and the counting numbers are CSS and a few lines of script), and what can start after the first paint does. To measure, start `truegetherth-start` from `.claude/launch.json` (the production build on port 3210), put `node scripts/perf/delay-proxy.mjs` in front of it, and run `scripts/perf/pagespeed-counts.mjs` (the score and what was counted; needs Lighthouse installed somewhere, `LIGHTHOUSE_DIR`) or `scripts/perf/first-paint.mjs` (the first layout, whether the scripts ran before the paint, the largest paint); R9 and R10 have the numbers and what was tried.
- `npm run test:e2e` runs Playwright against the production build; on this machine use `E2E_PORT=3210 npx playwright test` after `npm run build`. Suites that write (Admin, leads) only run against the local Supabase stack (`npm run db:start`, then `npm run db:test` and `npm run test:e2e:local`; needs Docker) and skip otherwise. In Claude Cloud, run `bash scripts/cloud/supabase-images.sh` before `db:start` and set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium`.
- `tests/e2e/home-landing.spec.ts` checks what fails silently on the home page: each stage pins and never scrolls sideways, every layer of the painting has its picture and floats, the layers shift with the pointer and part with the scroll, the router and its True Online mark stay clear of the headline and the navigation on several screen shapes, the inked sentence lies on its duplicate, the package row stops flush and follows its tab, the slip prints step by step, and the page with reduced motion, without scripts and on a short screen.
- `node scripts/media/shots.mjs` saves screenshots along the home page's scroll, and `--pages /broadband /service …` whole pages, to `shots/` (git-ignored). In Git Bash prefix commands that take `/paths` with `MSYS_NO_PATHCONV=1`.
- `npm run test:smoke` (read-only checks of a deployed site), `db:backup:dev`/`db:backup:local`/`db:restore:local` and `scripts/perf/lab-vitals.mjs` are described in `docs/renovation/M6-LAUNCH.md`.
