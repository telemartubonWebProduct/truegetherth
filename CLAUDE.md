## What the site is

Public pages collect contact-back leads from all of Thailand for True home internet and mobile packages, and keep W&W Energy solar. Thai is served at the old site's URLs (`/`, `/broadband`, `/monthy`, …), English under `/en`. Each language has its own root layout in a route group (`src/app/(th)`, `src/app/(en)`), so there is no rewrite (the old `[locale]` + rewrite broke RSC requests on Vercel). The page files in those folders are generated: edit `src/content/routes.ts` and `scripts/routes/generate.mjs`, then run `node scripts/routes/generate.mjs`. Shared layout and route helpers are in `src/app/_site`. `src/app/global-not-found.tsx` is the 404 for both languages. Preserve the old public URLs or add tested redirects; `tests/e2e/public-routes.spec.ts` covers them.

Pages render the validated content in `src/content` through `src/lib/content` with the components in `src/components/site`; every visible string needs both `th` and `en`. Public pages read the published release from Supabase and fall back to `src/content`. Content schema changes bump `CONTENT_SCHEMA_VERSION` (now 5: the home page became the scroll landing); a published release of another version is not shown until it is published again. Components in `src/components/site` also render in the editor's in-browser preview, so they must not import server-only modules; pass server facts in through `RenderContext`.

The back office (`/admin`, one invite-only Admin role): the Mirror editor (`src/components/editor`, `src/app/admin/(editor)`) mirrors the public page and edits every content, media, CTA and theme value in a fixed layout; it builds its fields from the content schema, so a new schema field needs a Thai label in `src/components/editor/labels.ts` (a unit test enforces it), and structural keys stay read-only. Catalog and media management, publish/history/rollback, the lead inbox and the report are under `src/app/admin/(console)`. The lead form stores requests with the server-only `SUPABASE_SECRET_KEY`; without it the contact page offers LINE and phone instead.

## Look and motion

Minimal black and white: white canvas, near-black ink (`#0b0b0c`) for text, buttons and dark sections, Inter (Latin) and Anuphan (Thai) from `src/fonts` set light, pill buttons and a floating pill navigation on every page. Red is rationed to marks: prices, meters, the live step. Colours are theme tokens (`src/styles/tokens.css`, defaults in `src/lib/content/theme.ts`, editable in site settings with contrast checks); `src/app/globals.css` (Tailwind 3 plus shared classes) holds what every page shares, and `src/styles/landing.css` (plain CSS) the home page's stages, the navigation and the motion.

The home page (`src/components/site/home`, rendered by `Landing.tsx` from `pages.home`) is five pinned stages — hero, manifesto, the rail of recommended packages (a tab per category), the slip that prints the four steps, services — then a price table and questions. `ScrollDriver.tsx` is the page's one scroll handler: it only writes custom properties on `<html>` and switches a few attributes; the CSS does the rest; Lenis smooths wheel scrolling. The choreography applies only under `html[data-motion]`, set before first paint by the site layout when the visitor has not asked for reduced motion and the screen is at least 560px tall. Without it (no JavaScript, reduced motion, a short screen, and the editor's preview, which is locked flat) every section lies flat and fully visible. Keep that true for anything new: base styles are the flat layout, motion goes under `html[data-motion]`. A pinned stage must fit one screen at any height (`node scripts/media/stage-sizes.mjs rail` checks nine sizes).

### The hero picture

- **The router** is modelled in code with Blender: `scripts/blender/router.py` builds it (measurements by eye from `design/hero/router/reference-true-wifi7.webp`), bakes ambient occlusion and the floor shadow with Cycles, and writes `public/models/router-v1.glb`, `router-v1-ao.webp`, `router-v1-floor.webp`. Run it as its header says (Blender 5.2 at `C:\Program Files\Blender Foundation\Blender 5.2`). The model and its bake must come from the same run. The logo on it is the True Online mark from the owner's own site assets (`design/hero/router/trueonline.png`): never generate or redraw a True logo.
- **The live scene** is `src/components/site/home/scene.ts` (three.js, loaded on demand by `Hero.tsx`). The baked maps are loaded as bitmaps on purpose (their orientation otherwise depended on upload order).
- **The still** (`public/media/hero-v3/poster-*.webp`, media id `hero-router-still`) is the scene's own first frame, taken by `node scripts/media/hero-poster.mjs` against the running dev server; it prints the touch point for `src/components/site/home/hero-art.ts`. Take it again after any change to the model, the light or the camera at rest. The still is what shows first, and all that shows with reduced motion, without scripts, and where WebGL would run in software (a test browser is such a place).
- **The arm** is two pictures the owner generated on green (`design/hero/parts/`); `node scripts/media/hero-arm.mjs` cuts them out to `public/media/hero-v3/arm-*.webp` and prints the fingertip's position for `hero-art.ts`. `Hero.tsx` listens to the arm's CSS animations to switch the router's lights on.

A new picture or model goes in a new folder or name (`hero-v4`, `router-v2`): the files are cached for a week.

## Working here

Node 24.18.0 (`.nvmrc`); `package-lock.json` is authoritative. Next 16.3.7 with React 19.3: this version has breaking changes against older Next.js, so read the relevant guide in `node_modules/next/dist/docs/` before using an API you have not used in this version, and heed deprecation notices.

- `npm run dev -- --port 3200` (port 3000 belongs to another app of the owner's on this machine).
- Checks: `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run build`.
- `npm run test:e2e` runs Playwright against the production build; on this machine use `E2E_PORT=3210 npx playwright test` after `npm run build`. Suites that write (Admin, leads) only run against the local Supabase stack (`npm run db:start`, then `npm run db:test` and `npm run test:e2e:local`; needs Docker) and skip otherwise. In Claude Cloud, run `bash scripts/cloud/supabase-images.sh` before `db:start` and set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium`.
- `tests/e2e/home-landing.spec.ts` checks what fails silently on the home page: each stage pins and never scrolls sideways, the inked sentence lies on its duplicate, the package row stops flush and follows its tab, the slip prints step by step, the arm's finger ends on the antenna, the picture stays clear of the headline on several screen shapes, and the page with reduced motion, without scripts and on a short screen. A test browser draws WebGL in software, so there the hero keeps its still: look at the live scene in a real browser, or with `node scripts/media/hero-poster.mjs --look shots/look.png [--scroll 0.85]`.
- `node scripts/media/shots.mjs` saves screenshots along the home page's scroll, and `--pages /broadband /service …` whole pages, to `shots/` (git-ignored). In Git Bash prefix commands that take `/paths` with `MSYS_NO_PATHCONV=1`.
- `npm run test:smoke` (read-only checks of a deployed site), `db:backup:dev`/`db:backup:local`/`db:restore:local` and `scripts/perf/lab-vitals.mjs` are described in `docs/renovation/M6-LAUNCH.md`.
